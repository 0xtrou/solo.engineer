## Goal
Show per-article category keyword scoring on BOTH pages. All 5 scores visible per card, raw hit count. Reuse terminal's 5 categories (Power & grid, Policy & controls, Hardware & compute, Capital & costs, Technology & research) as the single shared vocabulary across both feeds.

## Phase 1 — Shared scoring module

**New file `lib/categories.ts`:**
- Export `SHARED_CATEGORIES` = terminal's 5 labels (as const) — single source of truth
- Export `type Category = (typeof SHARED_CATEGORIES)[number]`
- Export `categoryKeywords: Record<Category, string[]>` — move from `lib/terminal-feed.ts` (current location)
- Export `scoreCategories(text): Record<Category, number>` — counts keyword hits per category across the 5 buckets
- Export `categorizeArticle(title, summary, fallback): { category: Category; scores: Record<Category, number> }` — wraps `scoreCategories`, picks argmax for `category` + returns full scores

This module is imported by both `lib/terminal-feed.ts` (terminal) and `lib/topics.ts` (home). Single vocabulary, single keyword map, single scoring logic.

## Phase 2 — Terminal: wire shared scoring

**`lib/terminal-feed.ts`:**
- Remove the local `categoryKeywords` + `categorizeArticle` (now in `lib/categories.ts`)
- Import shared versions
- Add `categoryScores?: Record<Category, number>` to `TerminalArticle` type (line ~7)
- In `toArticles()` (~L482): call `categorizeArticle(entry.title, entry.summary, source.category)`, assign both `category` and `categoryScores` to the article object

**`packages/contracts/src/terminal.ts`:**
- Add `categoryScores: z.record(z.enum(terminalCategoryLabels), z.number()).optional()` to `terminalArticleSchema`

**`lib/client/terminal-api.ts` `fromCanonical()`:**
- Recompute `categoryScores` client-side via `scoreCategories` on title+excerpt (canonical server doesn't emit scores; cheap recompute, no API change needed)

## Risks & notes
- **Shared category vocab fit on home:** terms like "Power & grid" fit awkwardly on dev/research posts, but user chose unified vocab — many home items will score 0 across all 5 (row renders all-zeros). Mitigation: only render the row if max score > 0 (hide zero-score cards). This keeps home clean while still surfacing real signals.
- **Contracts schema drift:** `feed.ts` schema is already missing `tier`; this PR fixes both `tier` + `categoryScores` there.
- **Canonical API path:** server doesn't emit scores; recompute client-side in `fromCanonical` (cheap, no server deploy).
- **No e2e assertions on new rows** — additive only; existing testids unchanged.
